# وثيقة مواصفات شاشة: مخزون البدل والقطع الفردية (Suits Inventory)
**المسار في النظام:** `pages/SUITS-INVENTORY.md`  
**المرحلة:** Phase 1 (Documentation)  

---

## 1. الهدف الوظيفي (Goal)
إدارة موديلات البدل ووحداتها الفردية المميزة بباركود فريد، وتتبع دورة حياة كل قطعة وحالتها (متاحة، محجوزة، قيد الاستخدام، في المغسلة، تحت الصيانة، تالفة).

## 2. بنية واجهة المستخدم (UI Layout)
جدول متقدم مع فلترة حسب الموديل، المقاس، اللون، المخزن، والحالة التشغيلية، مع شريط بحث سريع ونافذة منبثقة لتفاصيل القطعة وسجل حركاتها.

## 3. المكونات المستخدمة (Components)
- `AppTable`
- `AppBadge`
- `AppSearch`
- `AppModal`
- `AppButton`
- `AppSelect`
- `BarcodeBadge`

## 4. الحقول والبيانات (Fields & Data Model)
- كود الوحدة (Barcode/QR)
- اسم الموديل
- المقاس
- اللون
- المخزن/الفرع
- سعر البيع
- سعر الإيجار لليوم
- مبلغ التأمين الافتراضي
- الحالة التشغيلية
- عدد مرات التأجير السابقة

## 5. الإجراءات المتاحة (Actions)
- إضافة موديل جديد
- إضافة وحدة فردية بباركود
- تعديل حالة القطعة
- نقل القطعة لمخزن/مغسلة
- طباعة باركود القطعة
- عرض سجل الحجوزات السابقة والقادمة للقطعة

## 6. القواعد التجارية المطبقة (Business Rules)
يمنع حذف أي وحدة فردية ارتبطت بحجوزات سابقة؛ لا يمكن تحويل حالة القطعة إلى متاحة إذا كانت مرتبطة بحجز جارٍ؛ الباركود يجب أن يكون فريدًا عالميًا.

## 7. عمليات قاعدة البيانات (Database Operations)
عمليات على suit_models, suit_units, unit_status_history, cleaning_records مع Transactions عند تغيير الحالة.

## 8. حالات الواجهة (States: Loading, Empty, Error, Success)
Loading Skeleton، Empty State مع زر إضافة أول بدلة، Error Dialog عند تعارض الكود أو تعثر الاتصال.

## 9. التحقق من صحة المدخلات (Validation Rules)
التحقق من فرادة الباركود، التحقق من إيجابية الأسعار والمقاسات الصحيحة.

## 10. خطة الاختبارات (Automated & Manual Tests)
- [ ] اختبار إضافة موديل ووحدات فردية متعددة
- [ ] اختبار منع تكرار الباركود
- [ ] اختبار حفظ تاريخ تغير الحالات بدقة

## 11. معايير القبول (Acceptance Criteria)
إمكانية فرز وبحث آلاف البدل فورياً وتتبع دورة حياة كل بدلة برقمها المميز.
